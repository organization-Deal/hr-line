## วิธีทำงานใหม่

### 1. เตรียมรอบเงินเดือน

สร้างรอบโดยตรวจเดือน ช่วงรอบ และวันจ่าย ระบบใช้โปรไฟล์เงินเดือน รายการประจำ เวลาเข้างาน และใบลาของรอบตามกลไกเดิม

มี “สร้างเดือนถัดไป” จากรอบที่กำลังดู เปิดให้ตรวจวันก่อนสร้าง ไม่สร้างทันที ถ้ามีรอบเดือนนั้นอยู่จะเปิดรอบเดิม ไม่ทับรอบเก่า โบนัส รายการพิเศษ และค่าแก้เฉพาะรอบเดิมไม่ถูกคัดลอกไปเอง

แยกจำนวน “พนักงานตามช่วงงาน / มีผลคำนวณ / ข้อมูลพร้อมตรวจ” และติดชื่อชัดให้จำนวนโปรไฟล์ที่พร้อมทั้งบริษัท หากมีคนเข้าเงื่อนไขแต่ยังไม่มีผลคำนวณ มีรายชื่อให้เปิดโปรไฟล์และกดคำนวณใหม่หลังตั้งค่า

สรุปด้านบนอิงรอบที่กำลังดู และจำนวนคนในรายการรอบอิง payroll_items จริง แทนจำนวน snapshot ที่อาจเก่า

### 2. ตรวจยอดและปรับรายการ

เรียงคนที่ต้องแก้และควรตรวจไว้ก่อน พร้อมปุ่มกรอง “ต้องแก้ / ควรตรวจ / ดูทั้งหมด” และข้อความกรณีไม่พบข้อมูล

เน้นคนที่ยอดรับสุทธิเปลี่ยน คนที่ยังไม่มีรอบก่อนเทียบ คนที่มีรายการพิเศษหรือปรับค่าเฉพาะรอบ รวมข้อผิดพลาดเดิม คนหนึ่งมีหลายประเด็นนับเป็นหนึ่งคนในตัวกรอง

กดชื่อพนักงานเพื่อดู “ทำไมได้รับยอดนี้” จาก breakdown และยอดที่บันทึกจริง ระบุเต็มรอบ คิดตามช่วงงาน ปรับวัน หรือปรับยอดเอง พร้อมเปิดแก้โปรไฟล์/บัญชีหรือเพิ่มรายการพิเศษของคนนี้ได้

เมื่อกดตรวจยอดแล้ว ระบบบันทึกรอบเข้าสู่การอนุมัติ ไม่มีการดาวน์โหลดไฟล์เองทันที และยังไม่โอนเงินหรือส่งสลิป

### 3. อนุมัติและเตรียมจ่าย

ตรวจสรุปก่อนยืนยัน ระบบยังเคารพ Maker–Checker หากเปิดไว้ ผู้สร้างรอบต้องรอผู้อนุมัติอีกบัญชี ผู้มีสิทธิ์ยืนยันอนุมัติและป้องกันแก้ตัวเลขผ่านหน้าตรวจสรุปเดียว จึงไม่ต้องจำ “Lock” เป็นอีกขั้นแยก

เมื่อพร้อมจ่าย: ดาวน์โหลดรายชื่อและยอดโอน → โอนผ่านธนาคารเอง → บันทึกว่าจ่ายเงินจริงครบแล้ว → ส่งสลิป

**ระบบนี้ไม่ได้เชื่อมโอนเงินอัตโนมัติ และไม่ได้ตรวจผลจากธนาคาร** ปุ่มบันทึกการจ่ายเป็นการยืนยันโดยผู้ใช้ ต้องระบุวันที่ อ้างอิง/หมายเหตุ และยืนยันว่าจ่ายครบตามรายชื่อและยอด ระบบตรวจยอด/เวอร์ชันป้องกันบันทึกจากหน้าที่เก่า

การอนุมัติ การจ่ายเงินจริง และการส่งสลิปเป็นคนละเรื่อง “ส่งสลิปแล้ว” ไม่ถูกแสดงว่าจ่ายแล้วโดยอัตโนมัติ รวมถึงรอบเก่าที่เคยส่งสลิปก่อนอัปเดตนี้

หน้าที่นำทางใหม่พาให้บันทึกการจ่ายก่อนส่งสลิป ส่วน API/เครื่องมือออกสลิปเดิมยังคงความสามารถเดิม ไม่เพิ่มข้อบังคับย้อนหลังว่ารอบเก่าต้องมีบันทึกการจ่ายถึงสร้างสลิปได้

## การบันทึกและแก้ไข

เพิ่มตาราง payroll_payment_confirmations และดัชนีกันยืนยันซ้ำ ระบบสร้างอัตโนมัติเมื่ออ่านรอบ/ใช้งาน หากใช้ migration เป็นมาตรฐาน สามารถรัน 0043_payroll_payment_confirmation.sql ผ่านขั้นตอนเดิมได้ ไม่มี DROP และไม่เขียนทับยอดเงินเดือน

เก็บวันจ่าย ยอด จำนวนคน เลขอ้างอิง ผู้ยืนยัน และเวลายืนยัน ใช้ snapshot ของรอบก่อนบันทึก การกดซ้ำไม่สร้างการจ่ายซ้ำ

เจ้าของ/เจ้าของร่วม/ผู้ดูแล HR แก้บันทึกการจ่ายได้โดยต้องให้เหตุผล เก็บแถวเดิมเป็น void ไม่ลบประวัติ และแสดงการดำเนินการในประวัติรอบ การแก้บันทึกไม่คืนเงินหรือยกเลิกธุรกรรมธนาคาร

รอบที่มีการยืนยันจ่ายแล้วจะเปิดกลับมาแก้ตัวเลขไม่ได้จนกว่าผู้มีสิทธิ์แก้บันทึกพร้อมเหตุผล ส่วนรอบที่ส่งสลิปแล้วคงข้อจำกัดแก้ไขเดิม ไม่ปลดล็อกย้อนหลังเอง

## ขอบเขตที่คงเดิม

- รักษารูปแบบหน้าจอและตารางเดิม เน้นทางเดินงาน ข้อความ และการเข้าถึงจุดแก้ไข
- ฟังก์ชัน recalculatePayrollPeriod ตรงกับ P10.20 ทุกตัวอักษร ตรวจด้วย hash ในชุดทดสอบ ไม่แก้สูตรภาษี ประกันสังคม วันคิดเงิน หรือกฎเงินเดือน
- ไม่คัดลอก adjustment/override ของรอบเก่า และไม่ทำรายการธนาคาร
- Notification Center, พรีวิวการ์ดเต็ม, Recruitment และสวัสดิการยังอยู่
