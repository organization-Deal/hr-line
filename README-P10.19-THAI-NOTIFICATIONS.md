# Nakna P10.19 — เขียนแจ้งเตือนด้วยภาษาไทยและดึงข้อมูลจากฟีเจอร์

อัปเดตจาก P10.18 เป็นไฟล์เพิ่ม/เปลี่ยนเท่านั้น วางรวมตามโฟลเดอร์เดิมแล้ว Deploy ทั้ง Worker และ public ไม่ต้องลบข้อมูลหรือรัน migration ใหม่

ต้องนำไฟล์ใหม่ src/notification-data.js, public/notification-editor.js และ public/notification-catalog.js ไปด้วย โดย Backend และ Frontend ใช้ catalog กลางเดียวกัน

ตรวจ /api/health ให้ release เป็น P10.19-NOTIFICATION-CENTER และหน้าเว็บเป็น UI P10.19

## ช่องข้อความแบบใหม่

- พิมพ์ข้อความตามปกติ กด “＋ เพิ่มข้อมูลในข้อความ” แล้วเลือกป้ายภาษาไทย เช่น ชื่อผู้รับ ชื่อบริษัท วันที่ เวลา และจำนวนจากฟีเจอร์นั้น
- ไม่ต้องพิมพ์วงเล็บหรือจำชื่อคีย์ ป้ายแสดงในเนื้อข้อความและกด × เพื่อลบได้
- กดแทรกตรงตำแหน่งที่กำลังพิมพ์ รองรับการพิมพ์ไทยและขึ้นบรรทัดใหม่
- มีตัวอย่างที่ใช้ชื่อ/จำนวนสมมติและชื่อบริษัทปัจจุบัน ดูได้ก่อนบันทึก ตอนส่งใช้ข้อมูลจริง
- กด “ใช้ข้อความแนะนำ” ได้ ข้อความเดิมที่เคยบันทึกไว้เปิดขึ้นมาเป็นป้ายให้เอง ไม่เปลี่ยนข้อความเก่าอัตโนมัติ
- คัดลอก/ตัดป้ายในช่องนี้ได้ โดยเก็บความหมายไว้เมื่อวางกลับในช่องแจ้งเตือน คัดลอกออกไปโปรแกรมอื่นเป็นป้ายภาษาไทยอ่านง่าย
- เนื้อหาที่วางจากเว็บเป็นข้อความธรรมดา ไม่อนุญาตให้ HTML/script ทำงาน

ป้ายที่แทรกได้จะตรงกับการแจ้งเตือนที่เลือก เช่น “จำนวนผู้สมัครรอติดต่อ” มีในรายการ Recruitment ส่วนสรุป HR มีจำนวนพนักงาน เช็กอิน ลา งานรออนุมัติ และเอกสารรอลงนาม ไม่อนุญาตให้สั่งอ่านตาราง/ข้อมูลส่วนบุคคลใด ๆ เองผ่านข้อความ

## การแจ้งเตือนเพิ่ม 8 รายการ

รวมกับเดิม 5 ประเภทเป็น 13 ประเภท รายการใหม่ปิดไว้ทั้งหมด ให้เลือกเปิดเองจากส่วน “เพิ่มการแจ้งเตือนจากฟีเจอร์อื่น” รายการที่เปิดจะขึ้นด้านบน ส่วนที่ยังปิดเก็บไว้ในส่วนพับ

| การแจ้งเตือน | ข้อมูลจริงที่อ่าน | เงื่อนไขส่ง |
| --- | --- | --- |
| เอกสารใกล้หมดอายุ | เอกสารที่ยังใช้งาน | หมดอายุวันนี้ถึงอีก 30 วัน |
| สัญญาจ้างใกล้สิ้นสุด | วันสิ้นสุดสัญญาของพนักงานที่ยังทำงาน | สิ้นสุดวันนี้ถึงอีก 30 วัน |
| ใกล้ครบกำหนดทดลองงาน | พนักงานสถานะทดลองงานที่ยังไม่ยืนยันผ่าน | ครบกำหนดแล้วหรือภายใน 7 วัน |
| หลักสูตรที่ยังเรียนไม่จบ | งานเรียนภาคบังคับของหลักสูตรที่เผยแพร่และพนักงานที่ยังทำงาน | ยังไม่สำเร็จและครบกำหนดแล้วหรือภายใน 3 วัน |
| KPI รออัปเดต | เป้าหมายที่เปิดใช้งานของพนักงานที่ยังทำงาน | ไม่มีการอัปเดตตามรอบรายวัน รายสัปดาห์ หรือรายเดือน |
| ผู้สมัครรอติดต่อ | ผู้สมัครใน Recruitment | สถานะ new หรือ screening ไม่อ่าน/นับทุกอีเมล |
| รอบเงินเดือนใกล้วันจ่าย | รอบเงินเดือน draft/review/locked | วันจ่ายผ่านมาแล้วหรือภายใน 3 วัน ไม่ส่งจำนวนเงินหรือเลขบัญชี |
| วันเกิดพนักงานวันนี้ | วันเกิดพนักงานที่ยังทำงาน | ตรงกับวันส่ง ไม่ส่งวันเกิด/อายุเต็มของบุคคล |

ส่งเมื่อจำนวนรายการมากกว่า 0 เท่านั้น ตั้งเวลา วัน และเลือกผู้รับได้ ส่งสรุปให้ HR/Owner ที่เชื่อม LINE และมีสิทธิ์ ไม่ส่งอัตโนมัติให้พนักงานทุกคนหรือผู้มีสิทธิ์เฉพาะ Manager/ผู้รับงาน HR แบบเดิม

การแจ้งเตือนงานเรียน/KPI เป็นสรุปถึง HR ไม่ใช่การส่งรายบุคคลถึงนักเรียนหรือเจ้าของ KPI รอบนี้

รายการใหม่ใช้รูปแบบการ์ดของแบรนด์เดิม สรุป HR รายวันยังใช้การ์ดเดิมจาก P10.18 พร้อมทั้งสองปุ่ม งาน HR และเอกสารครบเหมือนเดิม

ตรวจทุกนาทีภายในช่วงส่ง และส่งแยกผู้รับสูงสุดวันละครั้งต่อประเภทด้วยคิวเดิม ไม่ส่งย้อนหลังข้ามวัน รายการที่ยังไม่แก้จะมีสิทธิ์แจ้งใหม่ในวันที่เลือกถัดไป เลือกวันเดียวต่อสัปดาห์ได้หากไม่ต้องการเตือนทุกวัน

ใช้วันหยุดบริษัทตามระบบเดิม ยกเว้นวันเกิดซึ่งส่งได้แม้ตรงวันหยุดหากเลือกวันในสัปดาห์นั้นไว้

ถ้าข้อมูลต้นทางโหลดไม่ได้ ระบบแสดงสถานะผิดพลาดและไม่ส่งจำนวน 0 ที่เดาเอา การอัปเดตจะไม่ยิงซ้ำข้อความที่ส่งสำเร็จแล้วในวันเดียวกัน

ทดสอบ editor 32 จุด, แหล่งข้อมูลและตัวส่งใหม่ 55 จุด และชุดส่งเดิม 58 จุด รวม 145 จุดในสามชุดนี้ โดยทดสอบ SQLite จริงและจำลอง LINE ไม่ส่งข้อความจริงออกไป พร้อม regression การ์ดเดิม ตั้งค่าแจ้งเตือน Recruitment สวัสดิการ และเวอร์ชันผ่าน

ทดสอบ UI ระดับ state/DOM จำลองและโครงสร้าง Flex JSON ยังไม่ได้ตรวจภาพในแอป LINE หรือใช้งานกับเบราว์เซอร์จริงในรอบนี้ ยังไม่ได้ Deploy หรือยืนยันข้อมูล/การส่งในระบบจริงของบริษัท
