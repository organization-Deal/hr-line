# Nakna P10.30 — แก้ส่งสลิปไม่ผ่าน LINE

ฐาน: P10.29 เท่านั้น แพ็กเฉพาะไฟล์เพิ่ม/แก้ ไม่ใช่ Full source

สาเหตุที่พบในโค้ด
buildPayslipReadyFlex คืนค่า bubble โดยตรง แต่รายการ messages ของ LINE ต้องเป็นข้อความ flex ที่มี altText และ contents เป็น bubble จึงส่งรูปแบบผิดตั้งแต่ต้น

แก้ไข
- ครอบการ์ดสลิปเป็น Flex Message ที่ครบรูปแบบ โดยใช้หน้าตาและลิงก์สลิปเดิม
- ตรวจรูปแบบก่อนส่ง ไม่ยิงคำขอถ้าเป็น bubble เปล่า
- แยกข้อผิดพลาดรายคน เช่น การ์ดผิดรูปแบบ, Token ไม่ถูกต้อง, สิทธิ์ไม่ผ่าน, รหัสผู้รับไม่ถูกต้อง, โควตารายเดือนหมด, ส่งถี่เกินไป, LINE ขัดข้อง, timeout และเครือข่าย
- เก็บเฉพาะรหัสข้อผิดพลาดที่อนุญาต ไม่ส่ง token หรือรายละเอียดดิบของ provider ไปหน้าเว็บ
- แสดงเหตุผลภาษาไทยรายคน และรักษาไว้เมื่อรีเฟรช
- ไม่ลบประวัติหรือรีเซ็ตคนที่ส่งสำเร็จแล้ว

วิธีอัปเดต
1. วางไฟล์ public/ และ src/ ทับ P10.29 ตามโฟลเดอร์
2. Deploy Worker พร้อม static assets แล้วเปิดหน้าใหม่ ตรวจป้าย UI P10.30
3. เปิดรอบเดิม → เลือกผู้รับและส่งสลิป → ลองส่งคนที่ไม่สำเร็จอีกครั้ง
4. ไม่ต้องลบรอบ ไม่ต้องคำนวณใหม่ ไม่ต้องยืนยันจ่ายซ้ำ และไม่ต้องทำ migration เพิ่ม
5. หากยังส่งไม่ผ่าน อ่านเหตุผลใหม่ใต้ชื่อผู้รับเพื่อแก้การเชื่อมต่อหรือโควตาตามกรณี

การตรวจ
- ใช้ตัวสร้างการ์ดจริงใน src/index.js รวม shared LINE layout helpers ทดสอบรูปแบบคำขอจริงที่ออกจาก sender โดยใช้ provider จำลอง
- regression ตัว bubble เดิมถูกกันก่อนออกเครือข่าย และตัว Flex ที่แก้แล้วผ่าน transport
- ตรวจประเภทข้อผิดพลาดและการไม่เปิดเผย provider payload พร้อมการบันทึก/อ่านกลับจาก SQLite
- ไม่มีการส่ง LINE จริงหรือเปลี่ยนข้อมูลบริษัทจริง และยังไม่ได้ Deploy แพ็กนี้
- tests/ เป็นชุดทดสอบโค้ด ไม่ต้องตั้งเป็นเว็บไซต์
