# Nakna P10.24 — Dashboard อ่านง่ายและไม่มีเงินเดือน

แพตช์เฉพาะไฟล์เปลี่ยนจาก P10.23 ต้องติดตั้ง P10.23 ก่อน

## ติดตั้ง
วางทับตามโครงสร้างเดิม แล้ว Deploy ทั้ง src/ และ public/ ให้ครบ
ไฟล์ใหม่ที่ต้องเพิ่ม: src/dashboard-summary.js, public/dashboard.js, public/ui/dashboard.css และชุดทดสอบ
ไม่มีไฟล์ต้องลบ ไม่มี migration และไม่แก้ข้อมูลพนักงานหรือรายการเงินเดือนย้อนหลัง
หลัง Deploy โหลดใหม่ ตรวจเวอร์ชัน P10.24
หากแสดงข้อความรอสรุปแบบใหม่ ให้ตรวจว่า Worker และ frontend เป็น P10.24 ทั้งคู่

## เอาเงินเดือนออกจาก Dashboard
- ลบการ์ดเงินเดือน ยอดโอน และทางลัด Payroll ใน Dashboard
- /api/dashboard ไม่ query payroll_periods และไม่ส่ง payroll, gross_total หรือ net_total
- ลบ payroll จาก payload เก่าที่นำมา render และ cache เก่าเมื่ออ่าน รวมทั้งก่อนเขียน cache ใหม่
- ไม่ลบเมนูหรือความสามารถ Payroll ในหน้าของ Payroll เอง สูตรเงินเดือนไม่เปลี่ยน

## หน้าใหม่
- หัวหน้ากระชับ มีชื่อบริษัท วันที่ และเวลาอัปเดตจาก server (เวลาไทย)
- สรุปเข้างานเพียงชุดเดียว พร้อมกดดูรายชื่อของแต่ละกลุ่มจาก snapshot ชุดเดียวกัน
- งานรอจัดการแสดงงานที่ยังเปิดอยู่ ไม่ใช่แค่เรื่องที่ยังไม่อ่าน
- รวมผู้สมัครใหม่ เอกสารรอ HR ลงนาม คำขอลา คำขอพนักงาน และเรื่องส่วนตัวถึง HR ตามสิทธิ์เดิม
- กลุ่มผู้สมัครใหม่กับกลุ่มติดตามเกิน 3 วันไม่ซ้ำกัน
- กำหนดการใกล้ถึงเรียงตามวันที่ ใช้ชื่อภาษาไทย
- เอกสารและขั้นตอนรับสมัครแบบย่ออยู่ใน “ภาพรวมเพิ่มเติม” กดเปิดได้
- ยุบกล่องว่างเป็นข้อความสั้น ๆ ลดกรอบซ้ำและตัวเลขเข้างานซ้ำ
- บนมือถือแสดงงานรอจัดการก่อน แล้วสถานะทีมและกำหนดการ
- CSS จำกัดเฉพาะ Dashboard ไม่เปลี่ยนหน้า Payroll หรือหน้าอื่น

## นิยามตัวเลข
ใช้พนักงาน active ที่เริ่มงานแล้วและยังไม่พ้นวันสิ้นสุดงาน ตารางงานรายบุคคลมาก่อนแผนกและบริษัท ตามกติกาเดิม รวมวันหยุดบริษัท

คนมีตารางวันนี้แบ่งเป็น 3 กลุ่มที่ไม่ซ้ำกัน:
1. เช็กอินแล้ว (รวมผู้ที่มีวันลาแต่มีการลงเวลาด้วย)
2. มีวันลาที่อนุมัติและยังไม่เช็กอิน
3. ยังไม่เช็กอินและไม่มีวันลาที่อนุมัติ

สามกลุ่มรวมกันเท่ากับคนมีตารางวันนี้ การมีใบลาครึ่งวันยังแสดงว่ามีวันลา ไม่ได้ตัดสินว่าขาดงานทั้งวัน
มาสายเป็นกลุ่มย่อยของผู้ที่เช็กอินตามตาราง ไม่เอามาบวกเป็นจำนวนพนักงานอีกกลุ่ม
คนลงเวลานอกตาราง และคนมีวันลาแต่เช็กอินด้วยแสดงเป็นข้อมูลประกอบแยก
วันหยุดที่ไม่มีคนมีตารางจะแสดง 0 โดยไม่ใช้พนักงานทั้งบริษัทเป็นตัวหาร
ยังไม่เช็กอินไม่ได้หมายความว่าขาดงาน หรือเลยเวลาเริ่มกะแล้ว
รายชื่อจากแต่ละตัวเลขเปิดในกล่องดูรายชื่อ ไม่ได้บันทึกหรือแก้ข้อมูลใด ๆ

## ขอบเขตและการตรวจสอบ
- งานรอจัดการเป็นรายการตามสถานะที่ระบบติดตาม ปุ่มเปิดหน้าของฟีเจอร์นั้น ไม่ได้อนุมัติงานแทนผู้ใช้

- ชุดทดสอบการโหลด 28 จุด, หน้า Payroll 28 จุด และ Payroll 48 จุดผ่าน (SQLite จริงและ hash สูตรเดิม)

- ยังไม่ได้ทดสอบการแสดงผลจริงในเบราว์เซอร์หรือ Deploy ให้ และไม่ได้ส่ง LINE จริง
