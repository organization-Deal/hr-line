NAKNA P10.12 — เลือกรับเมลและแยกคิวสมัครงาน
แพตช์ต่อจาก P10.11 + VERSION_LABEL_FIX + BLANK_PAGE_HOTFIX ที่ส่งในแชตนี้

ติดตั้ง
1. อัป public/ และ tests/ ตามตำแหน่งเดิมใน Repository (รวม 6 ไฟล์)
2. รอ Cloudflare Deploy สำเร็จ แล้ว Ctrl+Shift+R
3. หน้าเว็บต้องแสดง UI P10.12
ไม่ต้องลบไฟล์ ไม่ต้อง Migration ไม่มี Backend ในแพตช์นี้
หากมีการแก้ Source เพิ่มนอกชุดในแชตหลัง P10.11 ให้เปรียบเทียบก่อนทับ app.js/index.html

วิธีใช้
1. บัญชี Gmail รับสมัครงาน → ปุ่ม เลือกรับเมล ข้าง hr.info@... (ไม่ใช่ Google หลัก · ขั้นสูง)
2. เลือกวิธี:
   - ค้นหาเมลที่น่าจะสมัครงาน: สร้าง Query คำสมัครงาน/Resume ให้ ไม่ต้องเขียนคำสั่งเอง
   - เฉพาะที่ HR ติดป้ายใน Gmail: ค่าเริ่มต้นชื่อ สมัครงาน แก้ชื่อป้ายได้ ต้องสร้าง Label และติดป้ายเมลใน Gmail ก่อน
3. ตรวจช่อง เปิดให้อ่าน Inbox / Sync อัตโนมัติ ตามที่ทีมต้องการ แล้วกดบันทึก
4. กด Sync ข้างบัญชีเพื่อใช้เงื่อนไขรอบใหม่
5. คิวหลักแสดง น่าจะเป็นใบสมัคร กดการ์ดตัวเลขเพื่อดู ไม่แน่ใจ / เมลทั่วไป / ทั้งหมด ได้
6. เลือกเมลแล้วกด รับเป็นผู้สมัคร จึงเข้าสู่ Pipeline การคัดออก/ลบจากคิว/กู้คืนยังใช้ได้

พฤติกรรม
- ใช้กฎคัดกรองเดิมบน Backend ไม่ได้เพิ่ม AI หรืออ่านเนื้อหา PDF/Resume
- แสดงเหตุผลการคัดจากหัวข้อ ข้อความตัวอย่าง และชื่อไฟล์แนบ
- เมลที่ HR กดรอตรวจจะไปกลุ่มไม่แน่ใจ แม้ระบบจัดว่าน่าจะสมัคร
- ไม่ลบเมลทั่วไปหรือเปลี่ยนสถานะให้ HR อัตโนมัติ ยังเปิดดูทุกกลุ่มได้
- เมลที่เคยนำเข้าก่อนเปลี่ยนเงื่อนไขยังอยู่ในประวัติ
- กรองผู้รับอย่างเดียวไม่รับประกันว่าเป็นใบสมัคร มีคำอธิบายเตือนในฟอร์มแล้ว
- ค้นหาจากคำอาจพลาดเมลที่เขียนไม่ชัด จึงต้องตรวจกลุ่มไม่แน่ใจ/ทั้งหมดเป็นระยะ
- Label ใช้ขอบเขต API เดิม: ย้อนหลังตามวันที่เลือก และไม่รวม Promotions/Social
- หยุดโหลดหน้าตั้งค่าแบบง่าย P10.8/P10.9 ที่เคยตั้งผู้รับเป็นบัญชีเดียวทั้ง Inbox ผ่าน index.html แล้ว เก็บไฟล์เดิมไว้ได้
- release.js รวมการแก้บั๊กหน้าขาวแล้ว โดยอัปเดตรุ่นเป็น P10.12
