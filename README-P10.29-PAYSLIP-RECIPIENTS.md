# Nakna P10.29 — เลือกผู้รับและส่งสลิปเงินเดือนผ่าน LINE

ฐานที่ต้องมี: P10.28
แพ็กนี้มีเฉพาะไฟล์เพิ่ม/แก้จาก P10.28 ไม่ใช่ Full source

ติดตั้ง
1. วาง public/ และ src/ ทับโฟลเดอร์เดิม แล้ว Deploy Worker พร้อม static assets
2. ไม่ต้องลบไฟล์เดิม ระบบสร้างตารางติดตามการส่งใหม่เมื่อเรียกใช้โดยผู้มีสิทธิ์ ไม่ต้องรัน migration เพิ่มสำหรับแพ็กนี้
3. เปิดหน้าใหม่ ตรวจเมนูด้านข้างต้องเป็น UI P10.29
4. tests/ เป็นชุดตรวจโค้ด ไม่ต้องตั้งเป็นเว็บไซต์

ใช้งาน
1. ตรวจและยืนยันยอดรอบเงินเดือน
2. โอนผ่านธนาคารเอง แล้วบันทึกว่าจ่ายเงินจริงแล้ว
3. กด “เลือกผู้รับและส่งสลิป”
4. กด “ส่งรายคน” หรือเลือกหลายคนด้วยช่องทำเครื่องหมาย
5. กด “เลือกที่ยังไม่ส่งทั้งหมด” หากต้องการส่งทุกคนที่ยังไม่ส่งและเชื่อม LINE แล้ว
6. กด “ส่งที่เลือก N คน” และยืนยันอีกครั้ง
7. ดูสถานะรายคนในหน้าต่าง คนที่ยังไม่เชื่อม LINE จะเลือกส่งไม่ได้ ส่วนคนที่ LINE รับคำขอแล้วจะถูกข้าม

ขอบเขต
- หน้าส่งใหม่นี้ส่งเฉพาะสลิปเงินเดือนผ่าน LINE ไม่ส่งอีเมล ไม่ส่งหลักฐานโอน และไม่โอนเงิน
- หากสลิปยังไม่พร้อม จะพยายามสร้างเฉพาะรายชื่อที่เลือกผ่าน Google Drive ก่อนส่ง
- สลิปที่พร้อมแล้วถูกใช้ซ้ำก่อนสร้าง/อัปโหลด PDF ใหม่ เพื่อลดไฟล์ซ้ำ
- มีคำยืนยันก่อนส่งทุกครั้ง เลือกทั้งหมดไม่ได้ส่งทันที
- รายการแบ่งส่งชุดละไม่เกิน 5 คนเพื่อแสดงความคืบหน้า
- มีการแยกบริษัท/รอบ/ผู้รับ ตรวจสิทธิ์ ตรวจข้อมูลรอบที่เปลี่ยน และบังคับมีบันทึกว่าจ่ายจริงก่อนส่ง
- มีสมุดสถานะการส่งและล็อกการส่งซ้อนรายคน ใช้ LINE retry key เดิมสำหรับลองคำขอเดิมซ้ำ
- “LINE รับคำขอแล้ว” หมายถึง API ยอมรับ ไม่ใช่หลักฐานว่าเปิดอ่านหรือได้รับบนโทรศัพท์
- ส่งบางคนยังไม่เปลี่ยนทั้งรอบเป็น Published จนกว่าทุกคนในรอบมีสถานะ LINE รับคำขอแล้ว
- คนที่ไม่มี LINE ยังค้างในรายชื่อเพื่อให้ HR เชื่อมบัญชีแล้วกลับมาส่งภายหลัง
- ยกเลิก endpoint Publish แบบเดิมที่ส่งทั้งหมดโดยไม่เลือกรายชื่อ จึงต้อง Deploy หน้าเว็บและ Worker พร้อมกัน

การตรวจ
- ทดสอบฟีเจอร์ใหม่ 39 checks ด้วย SQLite จริงและ LINE จำลอง: สิทธิ์ บริษัท รายชื่อผิด ข้อมูลเก่า การยืนยันจ่าย การเลือกคน ส่งซ้ำ ส่งพร้อมกัน ความล้มเหลว retry key การสร้างเฉพาะไฟล์ที่ขาด และข้อมูลที่ไม่ควรออก API
- Payroll workflow 48, Payroll review 28, Dashboard 76, Mobile performance 30, Mobile Dashboard 23, Notifications 66 พร้อม syntax และ release checks ผ่าน
- ไม่มีการส่ง LINE จริง ไม่มีการโอนเงินหรือแก้ข้อมูลบริษัทจริงระหว่างทดสอบ
- ยังไม่ได้ Deploy หรือทดสอบหน้าต่างใหม่นี้ในเบราว์เซอร์จริง
