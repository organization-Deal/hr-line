# Nakna P10.25 — ผู้ใช้งานและสิทธิ์

แพตช์เฉพาะไฟล์ที่เปลี่ยนจาก P10.24 ต้องติดตั้ง P10.24 ให้ครบก่อน
วางไฟล์ตามโครงสร้างเดิม แล้ว Deploy ทั้ง src/ และ public/
เพิ่มไฟล์ใหม่ src/access-management.js, public/access-ui.js และ public/ui/access.css ให้ครบ
ไม่มี migration ไม่มีไฟล์ที่ต้องลบ ไม่ได้เปลี่ยนสิทธิ์ผู้ใช้งานจริงระหว่างจัดทำแพตช์
หลัง Deploy ตรวจว่า UI แสดง P10.25

## วิธีใช้
ตั้งค่า → ผู้ใช้งานและสิทธิ์ แบ่ง 2 แท็บ:
- ผู้ดูแลระบบ: เจ้าของหลัก/เจ้าของร่วมจัดการได้ตามสิทธิ์เซิร์ฟเวอร์เดิม
- ผู้อนุมัติ: เจ้าของและ HR จัดการสิทธิ์รายพนักงานได้

รายชื่อใช้บทบาทภาษาไทย ซ่อนอีเมลระบบ @nakna.local และรูปที่เสียใช้ตัวอักษรแทน
กด “ดูและจัดการสิทธิ์” เพื่อดูบทบาท เปลี่ยนบทบาท หรือถอนสิทธิ์ ไม่แสดงปุ่มถอนสิทธิ์เป็นปุ่มหลักทุกแถว
เจ้าของหลักและบัญชีตัวเองเปิดอ่านได้ แต่เปลี่ยนหรือถอนสิทธิ์จากหน้านี้ไม่ได้ ตรวจทั้ง UI และ API
เพิ่มผู้ดูแล เลือกคน → เลือกบทบาท → ตรวจสิทธิ์ → ยืนยัน
เพิ่มผู้อนุมัติ เลือกคน → เลือกชุดสิทธิ์/กำหนดเอง → ตรวจสิทธิ์ → ยืนยัน
หน้าตรวจป้องกันการเปลี่ยนบริษัท/เปลี่ยนข้อมูลระหว่างตรวจและยืนยัน
บทบาทผู้ดูแล HR เข้าถึงงานเงินเดือนตามกติกาเดิมด้วย ข้อความสรุประบุไว้ก่อนให้สิทธิ์

## ขอบเขตการอนุมัติ
การให้ leave.approve ไม่ได้ตั้งผู้อนุมัติให้พนักงานทุกคนโดยอัตโนมัติ ต้องตั้งในข้อมูลพนักงานเดิม
รายการแสดงจำนวนคนที่มอบหมายจริง และกล่องรายละเอียดแสดงรายชื่อที่มอบหมาย พร้อมสถานะเชื่อม LINE
สิทธิ์บางรายการในระบบเดิมเตรียมไว้สำหรับอนาคต รอบนี้ติดป้ายให้ชัด ไม่ได้สร้างโมดูลอนุมัติเวลา/OT ใหม่
ถ้าถอน leave.approve จะล้างผู้อนุมัติที่มอบหมายและคำขอที่รออนุมัติตามพฤติกรรม backend เดิม โดยมีคำอธิบายก่อนยืนยัน
การถอนสิทธิ์ผู้ดูแลบริษัทไม่ลบบัญชีพนักงาน และไม่ล้างสิทธิ์ผู้อนุมัติที่แยกไว้ ระบบบอกผลนี้ในหน้าตรวจ
การเพิ่มผู้ดูแลยังเรียกการแจ้ง LINE เดิมเมื่อยืนยันบันทึกจริง ไม่ได้ส่ง LINE ในชุดทดสอบ

## ประวัติ
กดเปิดประวัติการเปลี่ยนสิทธิ์ โหลด 30 รายการล่าสุดจาก audit_logs เดิม แสดงชื่อผู้ทำ ผู้รับ และเวลาไทย
เจ้าของเห็นประวัติผู้ดูแลและผู้อนุมัติ HR เห็นเฉพาะประวัติผู้อนุมัติ
บทบาทอื่นถูกปฏิเสธจาก API ไม่ส่ง raw audit JSON กลับหน้าเว็บ
เปลี่ยนบทบาทมีการตรวจบทบาทเดิมก่อนบันทึก ป้องกันคนเปิดหน้าค้างเขียนทับสิทธิ์ที่เพิ่งเปลี่ยน
