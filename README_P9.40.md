# Nakna P9.40 — Unified Leave Dashboard

ฐานที่ใช้: P9.38 (ไม่ได้รวม P9.39 Holiday Skip ซึ่งยังไม่ได้ติดตั้ง)

## เปลี่ยนอะไรบ้าง
- รวมการ์ด `LEAVE OVERVIEW` และ `MONTHLY LEAVE LOG` ให้เหลือ **LEAVE ANALYTICS** การ์ดเดียว
- กรองวัน / เดือน / ปี / ช่วงกำหนดเอง / สะสมทั้งหมด, พนักงาน, แผนก, ประเภทการลา, สถานะ
- แสดงสรุปจำนวนครั้งลาอนุมัติ, วันลาจริงตามข้อมูลคำขอ, รออนุมัติ, รอหลักฐาน, ไม่อนุมัติ
- แสดงรายคนทุกคน รวมผู้ที่ไม่เคยลา, รายการคำขอ, สถานะปัจจุบัน, ผู้อนุมัติจริง, วันเวลายื่นคำขอ และเวลาอนุมัติที่มีบันทึก
- ตารางรายละเอียดแสดงครั้งละ 100 คำขอ และมีปุ่มเปลี่ยนหน้า
- Export CSV **สรุปรายพนักงานทั้งหมดที่ตรงตัวกรอง** ไม่จำกัด 100 คำขอ
- โหลดบนหน้า Leave เท่านั้น; ไม่ยิงสอง API ทุกครั้งที่ render ทั้งระบบ
- เพิ่ม timeout, Retry, กัน Response เก่าทับการเลือกช่วงใหม่, แยก Cache ตามบริษัท
- ซ่อม `.all()` ให้ `/api/leave-overview` รุ่นเก่า เพื่อความเข้ากันได้ระหว่างเปลี่ยน Cache

## วิธีติดตั้ง
นำไฟล์ทั้ง 3 ตัวจาก ZIP วางทับใน GitHub ตามเส้นทางจริง (อย่าวางที่ Root):
```
public/index.html
public/app.js
src/index.js
```
จากนั้นรอ CI Deploy หรือรัน `npx wrangler deploy` จาก Repo ที่มีไฟล์ครบ

ไม่มี Migration ใหม่ **ห้ามลบข้อมูลหรือรันคำสั่ง Reset DB**

## กติกาการนับ
- ลาอนุมัติ 1 ใบ = 1 ครั้ง แม้ใบลาครอบหลายวัน
- รออนุมัติ, รอหลักฐาน, ไม่อนุมัติ, ยกเลิก ไม่เพิ่มยอด `วันลาอนุมัติ`
- ช่วงวันที่กรองคือ **วันที่พนักงานลา** ไม่ใช่วันที่กดยื่น
- ใบลาคร่อมช่วงที่เลือก จะนับว่าเกี่ยวข้องกับช่วงนั้น และจำนวนวันในช่วงใช้การเฉลี่ยตามระยะเวลาปฏิทินเป็น **ค่าประมาณ** หากมีวันหยุดภายในใบลานั้น; ช่วงที่ครอบใบลาทั้งใบใช้วันจากฐานข้อมูลจริง
- ผู้อนุมัติและเวลาอาจว่างสำหรับประวัติที่ไม่เคยเก็บข้อมูลนี้ไว้

## การทดสอบหลัง Deploy
1. หน้า การลา ต้องมี Dashboard สรุป **การ์ดเดียว** และ Approval Queue ยังใช้งานได้
2. เลือก สะสมทั้งหมด → พนักงานชื่อหนึ่ง → ดูจำนวนครั้งและประวัติ
3. เลือก รายเดือนและสลับเดือน → ตรวจยอดกับคำขอจริง
4. เลือก รายวัน (รวมวันที่ไม่มีการลา) → ต้องแสดง 0 ได้ ไม่หมุนค้าง
5. เลือกสถานะ รออนุมัติ / ไม่อนุมัติ / อนุมัติแล้ว → จำนวนต้องตรงกับรายการ
6. กด Export CSV จากตัวกรองปัจจุบัน
7. ลองใบลาครึ่งวันและใบลาที่คร่อมเดือน ตรวจหมายเหตุการเฉลี่ย
8. ตรวจการสลับ Workspace ว่ารายงานไม่ปนข้อมูลบริษัทเดิม
9. หากหน้าแจ้ง error ให้ตรวจ Worker logs ของ `/api/leave-analytics`

## ข้อจำกัด
ยังไม่ได้ Deploy หรือทดสอบกับฐาน D1 จริงใน Production; SQL ทดสอบผ่านกับ SQLite จำลองและ source syntax ผ่าน

**สำคัญ:** P9.39 เป็นอีกแพตช์ที่แก้ `src/index.js` เช่นกัน หากจะนำฟีเจอร์ Holiday Skip มาใช้ภายหลัง ต้องรวม patch กับ P9.40 ไม่ใช่นำ `src/index.js` จาก P9.39 มาทับ เพราะจะทำให้ API รายงานใหม่นี้หายไป
