# Nakna P10.22 — ตรวจเงินเดือนให้ง่ายขึ้น

แพตช์เฉพาะไฟล์ที่เปลี่ยนจาก P10.21 ต้องมี P10.21 อยู่ก่อนแล้ว

## ติดตั้ง
วางไฟล์ตามโครงสร้างเดิมในโปรเจกต์ แล้ว Deploy ทั้ง Worker (src/) และหน้าเว็บ (public/)
ไม่ต้องลบไฟล์ ไม่เพิ่ม migration และไม่แก้ข้อมูลเงินเดือนย้อนหลัง
หลัง Deploy โหลดหน้าใหม่และตรวจว่าเวอร์ชันแสดง P10.22
ยังไม่ได้ Deploy หรือทดสอบบนระบบจริงให้

## วิธีใช้ใหม่
1. เลือกรอบเดือน ดูยอดสรุปในรอบเพียงชุดเดียว (แถบสรุปด้านบนที่ซ้ำถูกนำออก)
2. ตารางเริ่มต้นแสดง ชื่อ / รายรับรวม / รายการหัก / รับสุทธิ / สิ่งที่ต้องตรวจ
3. คนที่ต้องแก้อยู่ก่อน ตามด้วยคนที่ควรตรวจ แต่ละคนมีเหตุผลแสดงในแถว
4. กดดูรายละเอียดเพื่อดูที่มายอดและเหตุผลที่ต้องตรวจ
5. รอบฉบับร่าง/ตรวจยอดแล้ว มีปุ่มแก้โปรไฟล์ เพิ่มโบนัส เพิ่มรายการหัก และเปิดแก้วันหรือเงินเดือนเฉพาะรอบ
6. การแก้วันหรือเงินเดือนเฉพาะรอบยังใช้ API และสูตรเดิม บันทึกทันทีเมื่อแก้ค่าและออกจากช่องสำเร็จ แล้วปิดรายละเอียดเพื่อไม่ใช้ snapshot เก่า ต้องเปิดใหม่เพื่อดูยอดล่าสุด
7. เปิด “ตารางละเอียดสำหรับ HR” เมื่อต้องแก้หลายคนในตารางเดิม กด “สรุปเงินเดือน” เพื่อกลับ
8. ตัวกรองและคำค้นทำงานทั้งสองมุมมอง เมื่อเปลี่ยนเดือนจะกลับมุมมองสรุปและล้างตัวกรอง
9. ตรวจยอด → ส่งอนุมัติ → เตรียมจ่าย → บันทึกจ่ายจริงและส่งสลิป ตามกระบวนการ P10.21

## ลดข้อความที่ทำให้สับสน
- ซ่อนตัวนับความพร้อมทั้งบริษัทใน sidebar เมื่อกำลังดูรอบเดือน ใช้จำนวนคนตามช่วงรอบในตัวนับหลัก
- ไม่มีรอบก่อนให้เทียบเป็นข้อมูลประกอบ ไม่ใช่คำเตือนที่ทำให้ทุกคนขึ้น “ควรตรวจ”
- ยอดเปลี่ยนจากรอบก่อน รายการพิเศษ การแก้วันหรือเงินเดือน และข้อผิดพลาดเดิมยังแสดง
- ข้อความ “ข้อมูลพร้อมตรวจ” ไม่ใช่การรับรองว่าจ่ายเงินถูกต้อง ต้องตรวจและอนุมัติตามเดิม
- ไฟล์ส่งออก รายละเอียดข้อยกเว้น รายการปรับ และประวัติรอบอยู่ในส่วนที่กดเปิดได้
- ไม่มีการโอนเงินจริงอัตโนมัติ สถานะจ่ายเงินจริงกับสถานะส่งสลิปยังแยกกัน
