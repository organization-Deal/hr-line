# นากนะ P10.0 — Product UI Redesign

## แพตช์นี้คืออะไร
โค้ด Frontend สำหรับใช้งานกับ Nakna ฐาน P9.40 ที่ประกอบจากไฟล์ในบทสนทนา ไม่ใช่เว็บตัวอย่างแยก และไม่ใช่การสร้างระบบ HR ใหม่
เปลี่ยนโครงหน้า การนำทาง การแสดงตาราง/ฟอร์ม และหน้ามือถือ โดยใช้ state, handler, validation, endpoint และ response เดิม
ไม่มีการเข้าถึงหรือแก้ไข Production ในระหว่างทำงานนี้

## ติดตั้ง
1. สำรอง Repository หรือสร้าง branch แยกจากรุ่นที่ใช้งานจริงก่อน
2. แตก ZIP นอก Repository ตรวจว่าชุดปัจจุบันเป็น Frontend P9.40 ไม่มีการแก้เพิ่มนอกชุดนี้
3. ทางเลือกสำหรับตรวจความเข้ากันได้: `node tools/check-p10-compat.mjs /path/to/your-repo` โดยเรียกสคริปต์จากในแพ็กนี้ ก่อนคัดลอกไฟล์
4. คัดลอกโฟลเดอร์ `public` ในแพ็กทับตามตำแหน่งเดิม 9 ไฟล์ HTML/JS และเพิ่ม `public/ui` 4 ไฟล์
   ห้ามเอา `public/app.js` ไปทับ `app.js` ที่ Root และห้ามลบ `public` เดิมทั้งโฟลเดอร์
5. `docs/p10-ui` และ `tools` เป็นคู่มือ/ชุดตรวจ เก็บใน Repo ได้ แต่ไม่จำเป็นต่อ runtime
6. ในโฟลเดอร์โปรเจกต์ รัน `npm run check` แล้ว Deploy ตามวิธีเดิม หรือ `npx wrangler deploy`
7. ปิดหน้า LINE Browser เดิมแล้วเปิดใหม่ หรือ Hard refresh ในเว็บ หลังอัป Sidebar จะแสดง `UI P10.0`
   `window.__NAKNA_FRONTEND_BUILD` ต้องเป็น `P10.0-PRODUCT-UI`
   `window.NaknaUI.version` ต้องเป็น `P10.0-ui1`
8. ทดสอบด้วยบัญชีและข้อมูลทดสอบก่อนให้ทีมใช้งานจริง โดยเฉพาะ payroll, upload, approval และ Safari/LINE บนเครื่องจริง

**ไม่ต้อง Migration, ไม่เพิ่ม package/dependency ของแอป และไม่ต้องตั้งค่า API key ใหม่**
ต้องอัปทั้ง 13 ไฟล์ใน public เป็นชุดเดียว ไม่ใช่เปลี่ยน CSS อย่างเดียว

## ไฟล์โปรแกรมที่เปลี่ยน
- `public/index.html` และ `public/app.js`
- `public/attendance.html`, `public/leave.html`, `public/invite.html`
- `public/documents.html`, `public/hr-case.html`, `public/learn.html`, `public/wellness.html`
- เพิ่ม `public/ui/p10.css`, `public/ui/p10.js`, `public/ui/portal-p10.css`, `public/ui/nakna-mark.webp`

ไม่ส่ง src/index.js, migrations, wrangler.jsonc, package.json หรือ root mirror มาทับ
ไม่ลบฟอนต์ โลโก้เดิม เอกสารเก่า หรือไฟล์โปรแกรมเดิม

## สิ่งที่เปลี่ยนจริง
### หน้าหลักและการนำทาง
Sidebar และ Topbar ขนาดสม่ำเสมอ, มือถือใช้เมนูด้านข้างพร้อมปุ่มปิด/ESC และเมนูลัดล่าง, เนื้อหามีพื้นที่เฉพาะไม่ซ้อนกับปุ่มล่าง
เมนูลัดอิงปุ่มเดิมและสถานะซ่อน/ปิดของปุ่มเดิม ไม่เพิ่มสิทธิ์ให้ผู้ใช้ ไม่ซ่อนช่องทาง Help บนจอเล็ก

### Dashboard
ลดขนาดหัวเรื่องและการ์ด, แสดงตัวเลขก่อนปุ่มลัด, วางงานค้างให้เข้าถึงเร็วขึ้น
วันหยุดใช้ข้อความอธิบายบริบท แทนไอคอนเฉลิมฉลอง และไม่เปลี่ยนวิธีคำนวณ attendance

### พนักงาน
แสดงคอลัมน์หลักก่อนและเปิดทุกคอลัมน์ได้ บนมือถือมี โปรไฟล์ / เอกสาร / เพิ่มเติม
ปุ่มเพิ่มเติมเปิดปุ่มเดิมและข้อมูลรอง รวมเลขบัญชี เงินเดือน สัญญา วันเริ่มงาน โดยไม่สร้างข้อมูลซ้ำ
ลิงก์เชิญรวมในส่วนที่เปิด/ปิดได้ ไม่ให้ลิงก์หมดอายุหลายรายการดันรายชื่อพนักงานออกจากจอแรก

### การลา
หนึ่งชุดรายงาน/ตัวกรองเดิม แยกแท็บ ภาพรวม / รอจัดการ / ประวัติ / ปฏิทิน
รอจัดการแสดงเฉพาะ pending + awaiting_evidence ไม่ปนอนุมัติแล้ว และระบุว่าเป็นคิวรวม ไม่ได้อิงตัวกรองของรายงาน
ประวัติยังใช้ API /api/leave-analytics เดิม รองรับรายวัน เดือน ปี ช่วงวันที่ ทั้งหมด คน แผนก ประเภท สถานะ และ CSV เดิม
มือถือแสดงข้อมูลที่ต้องใช้ตัดสินใจพร้อมชื่อผู้ตัดสินใจ/เวลา ส่วนเหตุผลฉบับเต็มกดดูรายละเอียดได้
ชื่อในรายงานกดดูประวัติรายบุคคลได้ ปุ่มดูรายละเอียดเปิดหน้ารายละเอียดเดิม
ไม่มีการลบใบลา เปลี่ยนสิทธิ์ หรือคำนวณจำนวนวันใหม่ในแพตช์นี้

### Payroll
การ์ดภาพรวมสมดุล, มือถือแสดงชื่อและยอดสุทธิพร้อมรายได้/หัก/ความพร้อมก่อน
เปิด “แก้วัน / เงินเดือน / รายได้เพิ่ม” เพื่อใช้ input และ onchange เดิม รองรับครึ่งวัน เงินเดือน Commission KPI Incentive Bonus ตามเดิม
รอบ Locked/Published ยังคงห้ามแก้ตามตรรกะเดิม ตาราง Desktop และ Export/Review/Publish ยังอยู่ครบ
ตารางข้อมูลกว้างใช้การเลื่อนเฉพาะภายใน ไม่ซ่อนคอลัมน์เงินเพื่อบังคับให้พอดีจอ

### เอกสาร / เวลางาน / ทีม / Recruitment / Learning & KPI / Rewards / Analytics / Wellness / ตั้งค่า
ใช้มาตรฐานปุ่ม ฟิลด์ ตาราง สถานะ Toolbar ช่องค้นหา และ Dialog ร่วมกัน
ฟอร์มมือถือเลื่อนเนื้อหาได้โดยมีหัวและปุ่มบันทึก/ยกเลิกที่เข้าถึงได้
หน้า Settings กลับมาเลือกหมวดได้ มีปุ่มกลับจากหมวด ไม่เปลี่ยน POST/PATCH ของการตั้งค่า
Portal พนักงาน 7 หน้าได้รับเฉพาะ CSS/โลโก้/รูปแบบฟอร์มที่สอดคล้องกัน ไม่แตะ script กล้อง พิกัด LINE auth หรือ e-sign

## จุดผิดพลาดที่พบและแก้
1. renderAttendance เดิมอ้าง attendanceSummary/attendanceBody ที่ไม่มีใน HTML ปัจจุบัน ทำให้ renderAll หยุดก่อนวาดโมดูลถัดไป เพิ่มทางเข้าตัววาด work-log ที่มีอยู่แล้ว
2. CSS เก่าซ่อน #settingsHome แบบ !important ทำให้เลือก Settings โดยไม่มีหมวดค้างไว้เป็นหน้าว่าง แก้การแสดงผลตามสถานะจริง
3. ช่องข้อมูลมือถือรับ gap/ตำแหน่ง/ขนาดจากหลายแพตช์จนสูงผิดปกติ และบางคอลัมน์ไม่มี label เพิ่ม label จากหัวตารางจริง รองรับ rowspan/colspan
4. คำเตือนโหลดรายงานถูกซ่อนเหมือนคำบรรยายใน CSS มือถือ แยกสถานะโหลด/ข้อผิดพลาดให้มองเห็นและ Retry ได้

## สิ่งที่คงเดิม และขอบเขตที่ยังไม่ทำ
- Server, DB schema, payroll calculation, permissions, subscriptions, LINE/Google/R2 integration ไม่เปลี่ยน
- การปรับความเร็ว mutation ของ P9.35 และ unified API ของ P9.40 ยังคงอยู่
- แพตช์นี้ไม่รวม/ไม่ย้อน P9.39 holiday-skip และไม่แก้การส่ง LINE 13:00 หรือ check-in notification
- ปัญหาคิว LINE, โควตา, D1 latency, token Google และผลอนุมัติจริงต้องตรวจระบบจริงแยกต่างหาก
- เป็นการปรับ UI layer ร่วมทุกหน้าและจัด flow เชิงลึกใน Dashboard/People/Leave/Payroll/Settings ไม่ใช่การเขียนทุกโมดูลขึ้นใหม่
- ยังไม่ได้ทดสอบฟังก์ชันทุกปุ่มกับ Production หรือทุกชุดข้อมูลจริง ไม่ได้รองรับการขายโดยรับรองว่าไม่มีบั๊กหรือผ่านมาตรฐานทางกฎหมาย

## Rollback
เก็บสำเนา Frontend เดิมของคุณก่อนติดตั้งเป็นหลัก
มีแพ็ก rollback ที่แนบแยกซึ่งคืนเฉพาะ 9 ไฟล์เดิมของฐาน P9.40 แล้ว Deploy อีกครั้ง ไม่แตะ Backend/DB
ไฟล์ใหม่ใน public/ui ปล่อยไว้ได้เพราะ HTML เดิมไม่เรียกใช้ หรือค่อยลบหลังย้อนสำเร็จ
อย่าย้อนแค่ CSS อย่างเดียว เพราะ HTML หน้า Leave ได้จัดส่วนใหม่ไว้ด้วย

## ตรวจผลและทดสอบซ้ำ
ดู `QA_RESULTS.md` และไฟล์ JSON ที่มากับแพ็ก มีผลตรวจจริงแยกประเภท ไม่รวมเป็นตัวเลขอ้างว่าทดสอบฟีเจอร์ครบทุกกรณี
ชุด browser test อยู่ใน `tests/` ใช้ Chromium offline และ API จำลอง ไม่ส่งข้อมูลจริง
ติดตั้ง dependency สำหรับ QA เท่านั้น: `python -m pip install -r docs/p10-ui/tests/requirements.txt`
กำหนด NAKNA_PROJECT_DIR เป็นโฟลเดอร์ Repo ที่อัปแล้ว และ NAKNA_CHROMIUM_PATH เป็น browser executable เมื่อต้องการ
รัน matrix.py, regression.py, extended.py แต่ละตัว ชุดทดสอบจะสร้างภาพและผลลัพธ์ลงโฟลเดอร์ tests
