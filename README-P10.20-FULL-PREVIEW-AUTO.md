# Nakna P10.20 — พรีวิวการ์ดเต็มและบอกชัดว่าเป็นระบบ Auto

อัปเดตจาก P10.19 เฉพาะไฟล์เพิ่ม/เปลี่ยน วางทับตามโฟลเดอร์เดิมแล้ว Deploy Worker ทั้ง src และ public ไม่ต้องลบข้อมูลหรือเพิ่ม migration

ต้องนำ public/notification-preview.js ไปด้วย ตรวจ /api/health ให้ release เป็น P10.20-NOTIFICATION-CENTER และหน้าเว็บแสดง UI P10.20

## ผู้ใช้จะเห็นอะไร

- หน้าเมนูอธิบาย “AUTO · ระบบแจ้งเตือนอัตโนมัติ” พร้อมขั้นตอน เลือกเรื่อง → ตั้งวัน เวลา และผู้รับ → บันทึกพร้อมเปิดใช้งาน → ระบบตรวจและส่ง LINE เอง
- ในหน้าตั้งค่า มีตัวอย่างการ์ดเต็มด้านข้างบนจอใหญ่ และใต้ช่องตั้งค่าบนมือถือ
- เห็นหัวการ์ด กล่องข้อมูล รายชื่อคนยังไม่เช็กอิน งาน HR เอกสารค้าง และปุ่มท้ายการ์ดของสรุป HR แบบเดิมครบ
- รองรับพรีวิวทั้ง 13 ประเภทตามข้อมูลของแต่ละฟีเจอร์
- แก้ข้อความ ป้ายข้อมูล เวลา หรือผู้รับแล้วอัปเดตพรีวิวหลังหยุดแก้สั้น ๆ มีปุ่มอัปเดตข้อมูลเพื่อโหลดตัวเลขล่าสุด
- แสดงว่า “เมื่อบันทึก: เปิดส่งอัตโนมัติ” หรือ “เมื่อบันทึก: ปิดส่งอัตโนมัติ” ตามสวิตช์ที่กำลังแก้
- การ์ดที่ระบบส่งตามเวลามีข้อความ “ระบบแจ้งเตือนอัตโนมัติ” ด้วย ส่วนสรุป HR ที่ผู้ใช้เรียกดูเองยังบอกว่าเป็นสรุปตามคำขอ

## พรีวิวตรงกับระบบส่งอย่างไร

Backend ใช้ฟังก์ชันเตรียมข้อมูลและสร้าง Flex JSON ร่วมกันระหว่าง Cron กับ API พรีวิว ไม่สร้างตัวเลขตัวอย่างแยกอีกชุด

ตัวเลขเป็นข้อมูลล่าสุดตอนดูพรีวิว ไม่ใช่การคาดการณ์ถึงเวลาส่งในอนาคต หัวการ์ดใช้เวลาแจ้งเตือนที่กำลังแก้ ส่วนข้อความ “ข้อมูล ณ” ใช้เวลาอ่านข้อมูลจริง ชื่อผู้รับแตกต่างตามปลายทาง และพรีวิวเตือนเช็กอิน/เช็กเอาต์แสดงชื่อพนักงานเป็นตัวอย่างโดยแจ้งกำกับ

กรณีเลือกผู้รับที่มีสิทธิ์ต่างกัน พรีวิวใช้รูปแบบของผู้รับที่มีสิทธิ์จำกัดก่อน เพื่อไม่ทำให้เข้าใจว่าเรื่องส่วนตัว HR จะส่งให้ทุกคน ตอนส่งจริงยังสร้างตามสิทธิ์รายผู้รับเช่นเดิม

แสดงการ์ดผ่าน renderer บนเว็บ เนื้อหาและโครงสร้างมาจาก Flex JSON เดียวกับตัวส่ง สีและการตัดบรรทัดอาจต่างเล็กน้อยจากแอป LINE

หากไม่มีรายการตรงเงื่อนไขของฟีเจอร์ จะมีข้อความกำกับว่า “ตอนนี้ไม่มีรายการเข้าเงื่อนไข ระบบจะยังไม่ส่งรายการนี้” หากโหลดข้อมูลไม่ได้จะแสดงข้อผิดพลาด ไม่แทนด้วยตัวเลขสมมติ

## การดูพรีวิวไม่ใช่การส่ง

- POST /api/notification-center/preview รับค่าที่ยังไม่บันทึก เพื่อประกอบตัวอย่างเท่านั้น
- ตรวจสิทธิ์ HR/Owner ตรวจบริษัทจาก session และตรวจสิทธิ์ผู้รับ
- ไม่บันทึกค่าตั้งเวลา ไม่สร้าง delivery/outbox และไม่เรียก LINE API
- ปุ่มในการ์ดตัวอย่างกดใช้งานไม่ได้ ไม่มี postback/link ที่ทำงานจริง
- ค่าที่แก้จะมีผลเมื่อกดบันทึก การส่งจริงยังรอวัน เวลา สถานะเปิด และเงื่อนไขของรายการ
- ปุ่ม “ทดสอบส่งถึงฉัน” เดิมเป็นการส่งจริงแยกต่างหาก ไม่ถูกเรียกจากพรีวิว

ตรวจพรีวิว 25 จุด ครอบคลุมการ์ดเต็ม สีเดิม ปุ่มที่ไม่ทำงาน ข้อความปลอดภัย ค่าแก้ที่ยังไม่บันทึก การรอพิมพ์ การทิ้งผลลัพธ์เก่า และการปิดหน้าต่าง

ชุดส่งเดิมและ API พรีวิว 66 จุด แหล่งข้อมูลฟีเจอร์ 55 จุด และ editor 32 จุด ผ่าน รวมถึง regression การ์ด HR เดิม/ตั้งค่า/เวอร์ชัน และ syntax

ทดสอบด้วย SQLite จริงและ LINE จำลอง รวม state/DOM จำลอง ยังไม่ได้ Deploy ส่ง LINE จริง หรือตรวจภาพผ่านเบราว์เซอร์/แอป LINE จริงในรอบนี้
