# P10.46 — Payroll แบบพาทำทีละขั้น

แพตช์เฉพาะไฟล์ที่เพิ่มหรือแก้ไข ลงทับ P10.45 โดยคงโครงสร้างโฟลเดอร์เดิม อัปเดต frontend ให้ครบทั้ง HTML, JS และ CSS ไม่ต้อง migrate ฐานข้อมูล หลังอัปเดตกด Ctrl+Shift+R แล้วตรวจ UI P10.46

## การใช้งานใหม่

1. เลือกรอบจากช่องด้านบน แทนการ์ดแคบด้านซ้าย
2. ตรวจและแก้ยอด: แสดงจำนวนคนที่ต้องแก้/ควรตรวจ เปิดตรวจรายคน และยืนยันสรุปยอดก่อนส่งอนุมัติ
3. อนุมัติยอด: แยกจากการจ่ายเงิน ผู้สร้างรอบยังต้องรอผู้อนุมัติอีกบัญชีเมื่อบริษัทเปิดกติกานี้
4. จ่ายเงิน: ดาวน์โหลดรายชื่อและยอดโอน โอนผ่านธนาคาร แล้วกลับมายืนยันวันที่จ่ายและอ้างอิง
5. ส่งสลิป: เปิดเลือกผู้รับและดูผลการส่ง แสดงจำนวนที่ LINE รับคำขอแล้ว

แสดงปุ่มหลักของขั้นที่กำลังดูไว้ช่วงบนของพื้นที่งาน ขั้นถัดไปที่ยังทำไม่ได้จะกดไม่ได้ เปิดดูขั้นก่อนหน้าได้โดยไม่เปลี่ยนสถานะจริง ตารางตรวจ/แก้ยอดอยู่ในขั้น 2 ส่วน Export และการตั้งค่าเพิ่มเติมเก็บอยู่ในเมนู ไม่กระจายแข่งกับปุ่มหลัก

ข้อความ “ควรตรวจ” แยกจาก “ข้อมูลต้องแก้” และไม่บอกว่าตรวจครบเพียงเพราะมีผลคำนวณครบ ก่อนส่งตรวจมีหน้าสรุปที่ระบุชื่อและเหตุผล พร้อมช่องยืนยันที่ผู้ใช้ต้องเลือกเอง หากยอด รอบ หรือบริษัทเปลี่ยน ต้องเปิดสรุปใหม่

การเลือกรอบใหม่จะล้างหน้าที่มีปุ่มดำเนินการของรอบเก่าทันที พร้อมสถานะกำลังโหลดและปุ่มลองใหม่เมื่อโหลดล้มเหลว ผลตอบกลับที่ล่าช้าของรอบหรือบริษัทเก่าจะไม่ทับข้อมูลปัจจุบัน

## ข้อมูลและขอบเขต

ใช้การคำนวณ ยอดเงิน สิทธิ์ API การอนุมัติ บันทึกการจ่าย และการส่งสลิปเดิม ไม่แก้สูตรภาษี/ประกันสังคม และไม่เปลี่ยนยอดหรือสถานะเดิมให้อัตโนมัติ ไม่มีการโอนเงินจริงหรือส่ง LINE จากการเปิดหน้า/เปิดขั้นตอน

รอบเก่าที่ส่งสลิปแล้วแต่ยังไม่มีบันทึกจ่าย จะแสดงขั้นจ่ายเงินพร้อมข้อความอธิบาย จะไม่สรุปเองว่าจ่ายแล้ว การแสดงส่งสลิปครบหมายถึง LINE รับคำขอครบตามข้อมูลในระบบ ไม่ได้ยืนยันว่าพนักงานอ่านแล้ว

เมนูเอกสารหลังเงินเดือนที่เพิ่มใน P10.45 ยังอยู่ใต้ Payroll ตามเดิม

## ตรวจสอบแล้ว

- Chromium ใช้ renderPayroll/renderPayrollDetail และ handler จริงกับ API จำลอง: ตรวจยอด → ยืนยันสรุป → รอ/อนุมัติ → ปิดแก้ยอด → บันทึกจ่าย → เปิดส่งสลิป
- ปุ่มหลักหนึ่งปุ่มต่อขั้นที่มีงานให้ทำ, ช่องยืนยันไม่เลือกอัตโนมัติ, ค้นหา/กรองคนที่ควรตรวจ, ป้องกันส่งสรุปเก่า, maker/checker, ดาวน์โหลดรายชื่อ, ไม่ส่งสลิปอัตโนมัติหลังอนุมัติหรือบันทึกจ่าย
- ประวัติอ่านอย่างเดียว, รอบยกเลิก, คนข้อมูลไม่ครบ, ส่งสลิปแล้วแต่ยังไม่มีบันทึกจ่าย, ไม่พบ JavaScript errors
- หน้าจอ 1440 / 1024 / 768 / 390 / 320px ตรวจปุ่ม เลือกรอบ และการล้นหน้า พร้อมตรวจภาพภาษาไทย
- Unit: model ขั้นตอน, จำนวนผู้รับไม่ซ้ำ, ไม่แก้ข้อมูลต้นฉบับ, การสลับรอบ/บริษัทระหว่างโหลด, error/retry
- Regression ปัญหา next step เดิมและหน้าเอกสารหลังเงินเดือนผ่าน รวม syntax และ release checks

ทดสอบด้วยข้อมูลจำลอง ไม่แตะ production และยังไม่ได้ทดสอบกับ HR มือใหม่จริง ควรให้ HR ทดลองหนึ่งรอบด้วยข้อมูลทดสอบก่อนนำไปใช้รอบจ่ายจริง
